# i18n

> **Rules:** [`../rules/i18n.md`](../rules/i18n.md) — non-negotiables, checklists, common mistakes.

## Message Structure (`src/messages/`)

- `en.ts` — defines the `Messages` type (source of truth for all keys)
- `id.ts` — typed as `Messages`, Indonesian values
- `index.ts` — aggregation, locale list

## Adding a Key

```typescript
// 1. Add to Messages type in en.ts
export type Messages = {
  myFeature: {
    title: string
    save: string
  }
}

// 2. Add values to en.ts and id.ts in the same shape

// 3. Use in component:
const t = useTranslations('myFeature')
return <h1>{t('title')}</h1>
```

## Locale Resolution

No locale in URL paths. Resolved via `createIsomorphicFn` in `src/lib/i18n.utils.ts`:
- `getCurrentLocale()` — returns `defaultLocale` ('id') or user-chosen locale
- **Client**: reads from `localStorage` (key `locale`), falls back to cookie, falls back to `defaultLocale`
- **Server**: reads from `locale` cookie (set when user switches), falls back to `defaultLocale`
- **Switch**: `LanguageToggle` writes to both `localStorage` + cookie, then reloads the page

## Key Rules

- MUST use `useTranslations()` for every user-facing text string
- MUST define every key in the `Messages` type before using it
- MUST provide both `en` and `id` values for every key
- MUST use existing namespaces; add new ones as new top-level keys
- MUST wrap test components in `IntlProvider` with test messages
