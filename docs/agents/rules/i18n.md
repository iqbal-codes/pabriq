# i18n Rules

> **Reference:** [`../boilerplate/i18n.md`](../boilerplate/i18n.md) — message structure, locale resolution, adding keys workflow.

## Purpose

Controls translation coverage, namespace structure, and locale handling for all user-facing text.

## When To Read This

- Adding or editing a route page, component, or any JSX that renders text visible to users.
- Adding validation messages, toast notifications, empty states, column headers, or button labels.
- Reviewing a PR for hardcoded English/Indonesian strings.

## Current Project Pattern

**Library:** `use-intl` v4, configured at root in `src/routes/__root.tsx:80-83` via `IntlProvider`.

**Messages:** Type-safe message definitions live in:
- `src/messages/en.ts` — The `Messages` type + English values (source of truth for the type contract).
- `src/messages/id.ts` — Indonesian translations (typed as `Messages` from en.ts).
- `src/messages/index.ts` — Aggregation, locale list, and type exports.

**Supported locales:** `['en', 'id']` with `en` as default.

**Usage in components:** `useTranslations('namespace')` returns a function `t` used as `t('key')`.

```tsx
import { useTranslations } from 'use-intl'

function MyComponent() {
  const t = useTranslations('customers')
  return <h1>{t('title')}</h1>
}
```

Multiple namespaces in one component:
```tsx
const t = useTranslations('products')
const dt = useTranslations('dataTable')
const st = useTranslations('status')
```

**Locale resolution:** `src/lib/i18n.utils.ts` — `getCurrentLocale` uses `createIsomorphicFn` to extract locale from the URL path (e.g. `/id/products`) on both server and client. Ignored paths: `/admin/**`, `/api/**`.

**Testing with i18n:** Tests wrap components in `IntlProvider` with test messages — see `src/components/status-badge.test.tsx:25` and `src/components/confirm-dialog.test.tsx:15` for the pattern.

## Non-Negotiable Rules

- MUST use `useTranslations()` for every user-facing text string in JSX. MUST NOT hardcode display text.
- MUST use `getTranslations()` for any user-facing text computed outside JSX (e.g. within `beforeLoad` or `loader` that returns display data).
- MUST define every translation key in the `Messages` type in `src/messages/en.ts` before using it. The type contract is the authority.
- MUST provide both `en` and `id` values for every key. Missing keys cause type errors.
- MUST use the existing namespace structure. New namespaces MUST be added as new top-level keys in the `Messages` type.
- Namespace keys MUST use camelCase (e.g. `noCustomers`, `searchPlaceholder`).
- MUST wrap test components that use `useTranslations` in `IntlProvider` with a `messages` prop containing the keys the test exercises.
- MUST NOT use raw strings in `beforeLoad` `breadcrumb` or `pageTitle` values — these are keys passed to `useTranslations('breadcrumb')` and `useTranslations('app')`.

## Allowed Exceptions

- `src/features/pricing/engine.ts` contains hardcoded English error message strings — this is a deep domain module and not a UI component. If these messages ever surface to the UI, they must become translation keys.
- `src/features/admin/model.ts` contains hardcoded demo strings — this is legacy seed data.
- Locale URL handling in `src/lib/i18n.utils.ts` uses `window.location` and `new URL` — this is necessary for the isomorphic locale extraction and URL rewrite pattern.

## Implementation Checklist

1. Identify every user-visible string in the new code.
2. Check if the translation namespace already has a suitable key; reuse existing keys when possible.
3. If adding keys, update `src/messages/en.ts` type first, then add values to both `en.ts` and `id.ts`.
4. Use `useTranslations('namespace')` in the component.
5. Ensure tests wrap components in `IntlProvider` with the relevant test messages.

## Verification

Run typecheck — any missing key in `id.ts` causes a type error because `id.ts` is typed as `Messages`:

```
bun run typecheck
```

Manual check: scan the new JSX for any text that is not inside `{t('...')}` or `{dt('...')}` — only i18n function calls should produce visible text.

## Common Mistakes To Avoid

- Hardcoding `"Customers"` in a `<h1>` instead of using `{t('title')}`.
- Adding a key to `en.ts` but forgetting `id.ts` — the type check will catch this.
- Using a key in `beforeLoad` that doesn't exist in the `breadcrumb` namespace.
- Wrapping a component in `IntlProvider` in a test but forgetting to pass all the nested namespace keys needed (e.g. only passing `status` but the component also calls `useTranslations('common')`).
- Forgetting that `StatusBadge` internally calls `useTranslations('status')` — any test rendering a `StatusBadge` needs the `status` namespace messages.
